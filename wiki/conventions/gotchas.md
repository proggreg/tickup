# Known Gotchas

## 1. `desc` not `description` (critical)

The `Todos` DB column for a todo's description is `desc`. The `Task` interface field is also `desc`. `objectToSnake` does NOT rename `description` → `desc`.

**Impact**: Any MCP tool or API route that accepts a `description` input and passes it through `objectToSnake` will silently lose the value — it won't be saved to the DB.

**Fix**: Manually remap before the Supabase call:
```typescript
const { description, ...rest } = input
const todo = { ...rest, desc: description }
```

The `update-todo` MCP tool has this fix. Watch for this in any new tool that accepts todo description.

## 2. `TodoDialog` has independent list selection

`TodoDialog.vue` uses a local `selectedListId` ref, not `currentList.id`. When creating a todo from the dialog, the store's `addListId()` falls back to `currentList.id` only when `todo.listId` is not already set. Setting `newTodo.listId = selectedListId.value` happens before calling `addTodo()`.

Do not assume "creating a todo always puts it in the current list."

## 3. Dialog system — two separate consumers

`TodoDialog.vue` and the new-list dialog consume `useDialog()` directly, independently of `AppDialog.vue`. `AppDialog` is not the only dialog entry point. If you add a new dialog, decide: direct `useDialog()` consumer, or routed through `AppDialog`.

## 4. Optimistic update ID assignment

`addTodo()` assumes the newly created todo is always the last element in `currentList.todos` or `todaysTodos`. Race conditions (multiple rapid creates) could corrupt ID assignment. This is a known fragility.

## 5. `updateTodosId` checks route path

`updateTodosId` decides which array to update (`currentList.todos` vs `todaysTodos`) by checking `route.path.includes('list')`. If a user adds a todo from the dashboard (not on a list page), the id gets written to `todaysTodos`, not `currentList.todos`.

## 6. Supabase keys in runtime config

`supabaseUrl` and `supabaseAnonKey` are in `runtimeConfig.public`. The MCP auth utility reads `runtimeConfig.public.supabase` as `{ url, key }` (the shape provided by `@nuxtjs/supabase`). Don't confuse with `supabaseUrl` / `supabaseAnonKey` at the top level of `public`.

## 7. E2e tests need running dev server

Playwright starts the dev server via `webServer` config. Tests import from `e2e/fixtures/index.ts` not `@playwright/test`. Auth state comes from `user.json` (generated by global setup). If `user.json` is missing or stale, all tests fail with auth errors.

## 8. MCP tool tests make real HTTP calls

MCP integration tests in `test/unit/mcp/` call `localhost:3000/mcp` directly. They require the dev server running with `NODE_V8_COVERAGE` for coverage. Running `pnpm test:coverage` alone won't cover MCP tools — use `pnpm coverage` (full coverage script).
